# Project agent memory

- POM plugin `comfyui` (`pom-plugin-comfyui`), created from the POM `creating-pom-plugins` skill. The contract lives in the POM repository: `docs/subsystems/plugins-ui.md` and `docs/subsystems/enterprise-licensing.md`.
- `src/abi.rs` is the C ABI v1 boundary (entry `pom_comfyui_plugin_v1` in `src/lib.rs`); keep domain code out of it. `src/lib.rs` dispatches `host.*`, `ui.*`, `rpc.*` and `peer.*` operations; `src/context.rs` reads `host.configure`.
- `query` must answer at once: the node waits 3 s and one slow call blocks every other. Slow work (downloads, child processes, indexing) runs on a thread the plugin owns.
- The plugin host speaks IPC over its own stdin/stdout: any child process gets `Stdio::null()` for stdin and a log file for its output, never the inherited streams.
- Secrets (`gateway.api_key`, `host_api.token`, upstream tokens) never appear in `rpc.*` replies, `host.services`, logs or screens.
- `ui/manifest.json` is the `pom-plugin-ui/v1` screen contract; `release/manifest.json` is the release contract (ABI, feature set, preferences). `ui/src/host/runtime.ts` and `ui/src/host/ready.ts` are the only files that read `__POM_HOST__`. CSS classes use the `pb-` prefix, which `ui/build.mjs` renames to the plugin code.
- `scripts/build-ui.sh` generates the ignored `ui/dist/`; `scripts/package.sh` builds an installable artifact and the per-platform GitHub manifest. The POM local rebuild runs `development.rebuild` with the source read-only (`scripts/dev-ui.sh` writes to `POM_PLUGIN_OUT_DIR`).
- ComfyUI integration (mirrors `pom-plugin-hermes`): `lifecycle: on_demand`, full-bleed iframe of `/api/ui/plugins/comfyui/proxy/`. `src/installer.rs` pins the ComfyUI release tarball (`VERSION`/`SOURCE_URL`/`SOURCE_SHA`) and `uv` 0.13.5, creates `<plugin dir>/venv` with a managed Python 3.12 and installs `torch torchvision torchaudio -r requirements.txt` in ONE `uv pip install --torch-backend <cu130|cu128|rocm6.4|cpu|auto>` (`cu130` from NVIDIA driver 580: ComfyUI's comfy-kitchen CUDA kernels for int8/fp8 weights need it) so PyPI never swaps the GPU build. `.installed` holds `<sha> <backend>`; another backend (GPU change, `cpu_only`) reinstalls packages. Install steps run in their own process group (killed on stop); logs `install.log`, `bridge.log`, `comfyui.log` in the plugin dir.
- `runtime/bridge.py` (run by the venv Python with `-I`) starts ComfyUI with `--listen 127.0.0.1 --port <random> --base-directory <workspace>/.comfyui` plus `POM_COMFYUI_ARGS` (newline-separated, from preferences), in its own session; it checks `x-pom-plugin-token`, rewrites `Host` and `Origin` to the loopback server (ComfyUI's origin middleware 403s a mismatch), sends `Upgrade` once for `/ws`, strips `x-frame-options`/`set-cookie`, and on stdin EOF kills the process group. It exits when ComfyUI dies so the supervisor reports `error`.
- `runtime/pom_nodes.py` and `runtime/web/pom.js` are rewritten into `<home>/custom_nodes/pom_nodes/` on every start. In a browser ComfyUI's missing-model "Download" saves to the viewer's computer; `pom.js` sets `window.__comfyDesktop2.downloadModel` (the frontend's host hook) so it POSTs `/pom/models/download`, which fetches Hugging Face/Civitai files into the first POM model folder (`POM_MODEL_DIRS`) with room, as `<org>/<repo>/<file>` (`relative_destination`, which refuses a URL without both parts or with `.`/`..` segments, plus a realpath check that the target stays inside the folder; `choose_root`), then POSTs `host_api` `/catalog/refresh`; without model folders it falls back to ComfyUI's `models/<folder>`. `sync_links` reads `host_api` `GET /catalog/images` and keeps `models/<folder>/pom/<name>` symbolic links to POM's image files (`CATEGORY_FOLDERS`, `plan_links`, `sync_links_to`: only symlinks under `pom/` are created or removed, never a regular file; where a symlink cannot be made, as on Windows without the privilege, the file's own folder is registered with `folder_paths.add_model_folder_path`); beside them, `plan_aliases` adds a plain-name alias `models/<folder>/<file name>` (what templates and shared workflows ask for) when that name is free and no other catalog file shares it; the aliases it made are listed in `models/.pom-aliases.json` and only those are ever replaced or removed. The sync runs at import on a background thread, after each download and on `POST /pom/models/sync`, which `pom.js` calls when the page opens. `tests/test_pom_nodes.py` (stdlib `unittest`, ComfyUI modules stubbed) covers downloads and links. The node's gateway URL and key, its model folders (`host.configure.model_dirs`) and its `host_api` reach it only as `POM_OPENAI_BASE_URL`/`POM_API_KEY`, `POM_MODEL_DIRS` (newline-separated) and `POM_HOST_API_URL`/`POM_HOST_API_TOKEN` in ComfyUI's environment (`supervisor::bridge_env`; `bridge.py` passes its environment on). A change of any of them or of a preference (`Context::launch_identity`) restarts ComfyUI.
- Image model components served to the POM network (`src/components.rs`, `Served`): POM's `component.serve` (the node's `ComponentAssignment`, paths absolute and checked here) is accepted only on an installed ComfyUI and answers `{"status": "refused", "error"}` otherwise (POM reads that shape); `component.release {deploy_id}`; `component.upstream` gives the bridge's `{status, port, token}` only for a served component. The list lives in `<plugin dir>/served-components.json` and is mirrored (paths included) to `<home>/pom-served.json` for ComfyUI's POM nodes; nothing is written before something is served. `host.services` adds a kind `image` service (`comfyui-image`) listing the components with file names only, `waiting` until ComfyUI is installed. Serving launches ComfyUI.
- `runtime/pom_components.py` (installed as `custom_nodes/pom_nodes/components.py`, registered by `pom_nodes`) answers `POST /pom/component/{deploy_id}/{component}/{op}` for what `<home>/pom-served.json` lists (re-read on change): diffusion `load` (the client's recipe: `supported_models` config, `unet_config`, `model_base` class, model type, dtype) and `apply` (the model's own `apply_model` after `load_models_gpu`), text_encoder `encode` (`encode_from_tokens_scheduled`), vae `load`/`decode`/`encode`; one GPU job per component at a time, run off the event loop. Bodies are safetensors with `__metadata__.args`/`lists` (`pack`/`unpack`), never pickle.
- `runtime/pom_remote.py` (installed as `remote.py`, `install()` from `pom_nodes`) lists the network's components (`host_api` `GET /components`, 5 s cache) as `POM ▸ <name> ▸ <file>` after the local files of `diffusion_models`, `text_encoders` and `vae` (wrapping `folder_paths.get_filename_list`), and makes `UNETLoader`, `CLIPLoader` and `VAELoader` return stand-ins for those names: a `MODEL` rebuilt from ComfyUI's classes with `disable_unet_model_creation` whose instance `apply_model` runs remotely (the sampler, sampling and conditioning stay local), a `RemoteCLIP` and a `RemoteVAE`. Calls go to `host_api` `POST /component/...` with `x-pom-job` (the running prompt id); an error is `RuntimeError("<component> on <hostname>: <cause>")`. Weight patches (`ModelPatcher.add_patches`) on a remote model, ControlNet and images given to a remote text encoder are refused. Each ComfyUI execution that calls a network component is one POM request: the first call opens it (`host_api` `POST /image-job/begin`; a 429 means the machine's image budget is spent and stops the run before any GPU call), and ComfyUI's `execution_success|error|interrupted` events (seen by wrapping `PromptServer.instance.send_sync`) close it with the images decoded, size and step count (`/image-job/complete`). The ignored live test covers a served VAE end to end (`POM_COMFYUI_E2E_VAE`).
- Deploy from ComfyUI (admins): `pom.js` registers the `pom.deploy.open` command (menu **POM ▸ Deploy on POM**) only when `GET /pom/deploy/role` (`pom_nodes.deploy_role`, from `host_api` `/node`) says `principal` or `admin`. Its dialog calls `/pom/deploy/{deployments,files,deploy,undeploy}`, which `deploy_relay` passes to `host_api` `/image-deployments`, `/image-files`, `/image-deploy` and `/image-undeploy` and answers unchanged; the node checks the role (403 otherwise) and the choices, nothing is decided in the browser.
`scripts/build-ui.sh && POM_UI_REQUIRE_DIST=1 cargo test --locked && cargo fmt --check && cargo clippy --locked --all-targets -- -D warnings && tests/test_ci_plan.sh && python3 -m unittest discover -s tests -p 'test_*.py'`.
